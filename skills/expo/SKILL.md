# Expo: с чего начать

Плагин для тех, кто делает первое мобильное приложение. Он работает **поверх** официального плагина Expo (`expo@claude-plugins-official`): тот знает тонкости API, этот ведёт новичка по шагам и ловит типичные ошибки.

## 0. Новичок?

Человек впервые делает приложение, не уверен, что всё установлено, или в папке нет проекта → начни с `expo-pack:expo-setup`. Это главный путь: компьютер → аккаунт → проект → телефон.

## 1. Сначала проверь проект

Если в папке есть `package.json`:

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/expo-check.mjs" .
```

Если `${CLAUDE_PLUGIN_ROOT}` не подставился — это папка на два уровня выше «Base directory for this skill».

- Код 2 — это не Expo-проект. Новый проект → шаг 2.
- ❌ ошибки исправь до остальной работы (или скажи человеку, что их надо исправить и почему).
- ⚠️ предупреждения назови, но не блокируй ими задачу.
- После установки пакетов ещё раз: `npx expo-doctor` — он сверяет версии с SDK по сети.

## 2. Новый проект

```bash
npx create-expo-app@latest <имя> --template default
cd <имя>
npx expo start
```

Сразу после создания переходи в `expo-pack:expo-connect`: вход в Expo и подключение телефона. Имя — латиницей, без пробелов. Шаблон `default` уже содержит Expo Router и вкладки. Сразу задай в `app.json`: `name`, `android.package` и `ios.bundleIdentifier` вида `kg.фамилия.приложение` — после первой загрузки в магазин их не поменять.

## 3. Куда направить задачу

| Человек хочет | Скилл |
|---|---|
| Новичок, «настрой expo», на компьютере ничего не стоит, первый запуск | `expo-pack:expo-setup` |
| Связать iPhone или Android с проектом, открыть приложение на телефоне (в том числе сразу после создания проекта) | `expo-pack:expo-connect` |
| Запустить на телефоне, «не открывается QR», «не подключается», красный экран, Expo Go ругается | `expo-pack:expo-run-on-phone` |
| Проверить экран: загрузка, пусто, ошибка, тормозит, клавиатура закрывает поле | `expo-pack:expo-screen-quality` |
| APK другу, Google Play, App Store, обновить без магазина | `expo-pack:expo-release` |
| Навигация, вкладки, модалки | `expo:expo-router` |
| Красивые нативные экраны, стили, иконки | `expo:expo-native-ui`, `expo:expo-ui` |
| Анимации, жесты | `expo:expo-animation` |
| Запросы к API, кэш, офлайн | `expo:expo-data-fetching` |
| Обновить SDK | `expo:expo-upgrade` |
| Нативный модуль на Swift/Kotlin | `expo:expo-module` |

Скиллы `expo:*` — из официального плагина. Если его нет (скилл не загружается), скажи человеку поставить его:

```
/plugin install expo@claude-plugins-official
```

и продолжай по правилам ниже.

## 4. Общие правила

- **Пакеты только через `npx expo install <пакет>`**, не `npm install`: Expo подберёт версию под SDK. Разъехались версии → `npx expo install --fix`.
- **Документацию читай под SDK проекта**: `https://docs.expo.dev/versions/v<SDK>.0.0/...`, а не `latest`.
- **Expo Go — песочница.** В нём только библиотеки, встроенные в Expo Go. Нужна своя нативная библиотека (камера VisionCamera, Firebase, покупки, реклама) → dev-сборка: `npx expo install expo-dev-client` и `eas build --profile development`. Скрипт проверки ловит это сам.
- **Секреты не кладут в приложение.** Всё с префиксом `EXPO_PUBLIC_` видит любой, кто скачал приложение. Ключи с правом записи — только на сервере.
- **Одна правка — один запуск.** После изменения кода смотри результат на телефоне (Fast Refresh), прежде чем идти дальше.
- **Папки `ios/` и `android/`**: если их нет — не создавай без причины (`expo prebuild` делает это сам при сборке).

## 5. Как говорить с новичком

- Объясняй термин один раз и простыми словами: «бандл — весь твой JS-код одним файлом, Expo Go скачивает его с компьютера».
- Каждую команду — с тем, что человек должен увидеть: «появится QR-код и строка `Metro waiting on exp://192.168...`».
- Ошибку не прячь: покажи строку из лога, причину и одну команду для исправления.
- Не ставь пять библиотек «на будущее». Только то, что нужно сейчас.
